# ReconForge roadmap

The roadmap is ordered around researcher value and precision, not the number of integrated tools.

## Phase 0 — foundation

- [x] Separate repository and project identity
- [x] Stable observation model
- [x] Hypothesis/evidence model
- [x] Deterministic URL normalization
- [x] Conservative semantic classifier
- [x] Explainable confidence scoring
- [x] SQLite storage boundary
- [x] Tooling strategy and adapter contract

## Phase 1 — reconnaissance fabric

- [ ] Scope policy engine
- [ ] Run orchestration and resumability
- [ ] Adapter interface and process runner
- [ ] Subfinder adapter

- [ ] HTTPX adapter
- [ ] Katana adapter
- [ ] GAU adapter
- [ ] Wayback adapter
- [ ] Naabu adapter
- [ ] Nmap enrichment adapter

- [ ] Distributed workers

- [ ] Queryable research graph

## Performance objective

We will not claim a universal vulnerability success rate. Instead, every release should report measurable performance on a stable benchmark and track:

- top-N investigation precision
- false-positive rate
- duplicate rate
- N/A rate
- mean time to useful hypothesis
- percentage of queue items accepted by the researcher as worth manual investigation
